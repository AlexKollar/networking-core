# IPv6 Fundamentals (CIS 170/171 — CCNA)

## Why IPv6, In One Honest Paragraph

IPv4 offers about 4.3 billion addresses and they ran out at the registries years ago; NAT stretched the supply by hiding whole networks behind single public addresses, at the cost of end-to-end reachability. IPv6 uses **128-bit addresses** —340 undecillion of them — so subnets can be generous, NAT is unnecessary by design, and every device can hold a globally routable address again. IPv6 is not "IPv4 with bigger numbers": header, addressing, neighbor discovery, and configuration all changed.

## Anatomy and Notation

An IPv6 address is eight groups (**hextets**) of four hexadecimal digits, separated by colons:

```
2001:0db8:0000:0000:0000:ff00:0042:8329
```

Two compression rules shrink it — exams test both, and the rules are strict:

1. **Drop leading zeros** inside a hextet: `0db8` → `db8`, `0042` → `42`, `0000` → `0`.
2. **Replace one run of all-zero hextets with `::`** — the longest run (leftmost if tied), and **only once** in an address. Two `::` would make the original length unrecoverable.

Worked compressions (verified):

| Full form | Compressed | Rules applied |
|-----------|------------|---------------|
| `2001:0db8:0000:0000:0000:ff00:0042:8329` | `2001:db8::ff00:42:8329` | Leading zeros + one `::` for the three-zero run |
| `fe80:0000:0000:0000:0202:b3ff:fe1e:8329` | `fe80::202:b3ff:fe1e:8329` | `::` for the zero run, leading zeros elsewhere |
| `2001:0db8:0000:0001:0000:0000:0000:0001` | `2001:db8:0:1::1` | The *longest* run (three zeros) becomes `::`; the single zero stays as `0` |

Traps: `::` alone is the **unspecified address** (all zeros — "no address yet", IPv6's 0.0.0.0). `::1` is **loopback** (IPv6's 127.0.0.1). Hex digits are case-insensitive; lowercase is conventional. There is **no broadcast in IPv6** — multicast and anycast do that work.

## Prefixes and Subnetting

Structure: **global routing prefix + subnet ID + interface ID**. The standard LAN is a **/64**: 64 bits of network, 64 bits of host. Example (verified): from `2001:db8:acad::/48`, the first /64 subnets are `2001:db8:acad::/64`, `2001:db8:acad:1::/64`, `2001:db8:acad:2::/64`, `2001:db8:acad:3::/64` — the 4th hextet is the subnet field, giving 65,536 /64 LANs out of one /48. With /64 everywhere, subnetting becomes counting in that hextet, not borrowing host bits.

The interface ID is often built with **EUI-64**: split the 48-bit MAC, insert `FFFE` in the middle, and flip the U/L bit. Modern operating systems usually prefer **randomized/stable-privacy interface IDs** instead, because a MAC-derived address follows the device everywhere — know EUI-64 for the exam, expect privacy addresses in the field.

## Address Types — The Table to Memorize

| Type | Prefix / example | Scope and use |
|------|------------------|---------------|
| Global Unicast (GUA) | `2000::/3` — in practice addresses starting 2 or 3, e.g. `2001:db8::` (documentation) | Publicly routable, the IPv6 equivalent of a public IPv4 address |
| Link-Local (LLA) | `fe80::/10` — always `fe80::` through `febf::` | One link only, never routed. **Every** IPv6 interface generates one automatically; neighbor discovery and routing-protocol adjacency run on these |
| Unique Local (ULA) | `fc00::/7` — deployed range is `fd00::/8` with a random global ID | IPv6's private-address analogue (RFC 1918's cousin); site-local, not Internet-routed |
| Multicast | `ff00::/8` | One-to-many. Key groups: `ff02::1` all nodes on the link, `ff02::2` all routers on the link, `ff02::1:ff00:0/104` solicited-node multicast (used by neighbor discovery) |
| Loopback | `::1/128` | The host itself |
| Unspecified | `::/128` | No address yet — source address during autoconfiguration duplicate checks |
| Documentation | `2001:db8::/32` | Examples in books and labs — never assign it in production |

Exam habits: a host normally holds **several IPv6 addresses at once** (link-local + one or more GUAs) — this is normal, not a fault. Link-local addresses require a **zone/scope ID** (`%eth0`) when an OS must say *which* link, because the same fe80::/10 exists on every interface.

## Neighbor Discovery (NDP) Replaces ARP

IPv6 has **no ARP**. ICMPv6 Neighbor Discovery does the job and more:

- **Neighbor Solicitation / Advertisement (NS/NA)** — "who has this address?" / "I do, here is my MAC", using solicited-node multicast instead of broadcast.
- **Router Solicitation / Advertisement (RS/RA)** — hosts ask for, and routers periodically announce, the prefix, default gateway, and configuration flags on the link.
- **Duplicate Address Detection (DAD)** — before using an address, a host asks if anyone already owns it.

## Getting an Address: SLAAC vs DHCPv6

**SLAAC (Stateless Address Autoconfiguration):** the router's RA announces the /64 prefix; the host builds its own interface ID and combines them. No server, no leases, no records. The RA also names the default gateway. By itself, classic SLAAC does not hand out DNS (an extension, RDNSS, can) — which is why real networks often pair it with stateless DHCPv6 for options.

**DHCPv6 — two flavors, and the RA flags choose:**

- **Stateful DHCPv6** — like DHCPv4: a server assigns the address and keeps a lease state (RA sets the **M flag**).
- **Stateless DHCPv6** — SLAAC builds the address; DHCPv6 only supplies other options such as DNS (RA sets the **O flag**).

Critical field fact: **DHCPv6 never provides the default gateway** — the gateway always comes from the RA. Android famously does not support DHCPv6 at all, so a DHCPv6-only design breaks those devices.

## Transition Notes (Concept Level)

Dual-stack (run both protocols side by side) is the primary strategy and what exams default to. Tunneling (e.g. 6to4 historically, manual/GRE tunnels) carries IPv6 over IPv4 infrastructure; translation (NAT64/DNS64) lets IPv6-only hosts reach IPv4-only services. Know what each *is* and when it fits; deep mechanics are beyond the CCNA scope.
